# 스태프온리 (Staff Only)

매장 직원 전용 **유통기한 관리 + 필독 공지** 앱이에요.
점주와 알바만 들어오는 매장 전용 공간에서, 출근하면 홈에서 **오늘 뺄 상품**과 **필독 공지**를 확인하고, 처리 완료와 다음 날짜 입력을 한 화면에서 끝내요.

> 마트 봉지라면 매대를 관리하던 경험에서 시작했어요.
> 메모장에 "신라면 261203"처럼 적던 방식의 불편함(찾기 번거로움, 깜빡함, 인수인계, 단톡방에 묻히는 공지)을 해결하는 게 목표예요.

## 주요 기능

### 매대 유통기한
- **매대 구조:** 카테고리(예: 봉지라면) > 구역(A·B·C·D). 담당자와 임박 기준일(기본 30일)은 카테고리마다 정해요.
- **간단한 입력:** 상품명과 매대에서 가장 빠른 유통기한만 적어요. 날짜는 숫자 6자리 `YYMMDD`(숫자 키패드)로 입력하고, 바코드는 쓰지 않아요.
- **첫 등록:** 구역 단위로 연속 입력해요(상품명 → Enter → 날짜 → Enter). 진행률도 보여줘요.
- **오늘 뺄 상품**
  - 임박일 = 유통기한 − 임박 기준일이에요.
  - 근무 요일이 있으면 임박일이 **다음 근무일보다 앞인 상품**까지 오늘 목록에 넣어요. 쉬는 날 임박하는 상품도 놓치지 않게요.
  - 근무 요일이 없으면 임박일이 오늘이거나 지난 상품만 보여줘요.
  - 날짜는 모두 Asia/Seoul 기준이에요.
- **처리:** 빼두기 완료 → 다음으로 빠른 날짜 또는 재고 없음 → 처리 완료. 처리 직후 되돌리기도 할 수 있어요.
- **기간 지난 상품:** 홈 맨 위에서 따로 물어봐요. 빼뒀어요 / 폐기했어요 / 재고 없음 중에 골라요.
- **히스토리:** 누가, 언제, 어떤 상품을 처리했는지(이전 날짜 → 새 날짜, 폐기 여부) 남겨요.
- **메모:** 매대 메모와 상품 메모를 남길 수 있어요. 예: "뒤 박스에 재고 더 있음"

### 매장과 직원
- 점주가 매장을 만들면 **6자리 초대코드**가 나와요. 알바는 코드로 입장을 요청하고, 점주가 승인하거나 거절해요.
- 점주는 퇴사자의 접근을 해제할 수 있어요. 해제하면 그 사람이 맡던 매대의 담당자도 자동으로 비워져요.
- 알바는 매장마다 **근무 요일**을 따로 설정해요.
- **여러 매장** 지원: 점주가 여러 매장을 운영하거나 알바가 두 매장에서 일해도 홈 상단에서 바로 전환해요.

### 필독 공지
- 점주가 공지를 쓰고 필독으로 지정할 수 있어요.
- 필독 공지는 알바가 **확인했어요**를 누를 때까지 홈 배너와 공지 탭 알림 점으로 남아요.
- 점주는 확인한 사람과 아직 안 본 사람을 볼 수 있어요. 알바에게는 확인 인원 숫자만 보여요.

### 점주 관리 화면
담당자 없는 매대 경고, 입장 요청, 매대별 임박·기간 지남 수, 최근 처리 기록, 필독 확인 현황, 초대코드, 멤버 관리를 한 화면에서 봐요.

### 로그인
이메일, 구글, 카카오로 로그인할 수 있어요. 가입한 뒤 이름과 역할(점주/알바)을 고르면, 그에 맞는 첫 화면으로 안내해요.

## 보안 설계
- **모든 테이블에 RLS를 켰어요.** 같은 매장의 승인된 멤버만 그 매장 데이터를 읽을 수 있어요.
- **점주만 할 수 있는 일:** 매장 설정, 입장 승인, 담당자 변경, 공지 작성
- **점주와 그 매대 담당자만 할 수 있는 일:** 상품 등록, 수정, 처리
- **상태 변경은 DB 함수(RPC)로만:** 입장 요청, 승인, 처리, 되돌리기, 공지 확인처럼 상태가 바뀌는 작업은 정해진 함수로만 해요. 예를 들어 상품 갱신과 히스토리 기록은 한 번에 저장돼요.
- **수정자는 서버가 기록:** 상품을 고친 사람과 시각은 서버가 기록해서, 클라이언트가 보낸 값으로 속일 수 없어요.
- **키 관리:** 클라이언트에는 Supabase URL과 anon(publishable) key만 둬요. `service_role` key는 쓰지 않아요.

## 프로젝트 구조

```
src/
  auth/          로그인 상태 (AuthProvider)
  store/         현재 매장·멤버십 상태 (StoreProvider)
  lib/           Supabase 클라이언트, 날짜 계산, 데이터 훅
  components/    탭바, 매장 전환, 초대코드·유통기한 입력 등
  pages/         화면 (홈, 매대, 처리, 히스토리, 공지, 관리, 설정 …)
supabase/
  migrations/    DB 스키마 SQL (0001 → 0006 순서대로 적용)
docs/
  BACKLOG.md     나중에 할 일
```

## 로컬에서 실행하기

### 1. 준비
- Node.js 20 이상
- [Supabase](https://supabase.com) 프로젝트

### 2. 설치

```bash
git clone https://github.com/uploaddragon/staff-only.git
cd staff-only
npm install
```

### 3. 환경 변수
`.env.example`을 복사해서 `.env`를 만들고, Supabase **Project Settings → API Keys**의 값을 넣어요.

```
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_...
```

> `.env`는 `.gitignore`에 들어 있어서 커밋되지 않아요.

### 4. DB 스키마 적용
Supabase **SQL Editor**에서 `supabase/migrations/`의 파일을 **번호 순서대로** 실행해요.

| 파일 | 내용 |
|---|---|
| `0001_profiles.sql` | 프로필, 가입 시 자동 생성 |
| `0002_stores.sql` | 매장, 초대코드, 입장 승인, 근무 요일 |
| `0003_shelves.sql` | 카테고리, 구역, 상품 |
| `0004_processing.sql` | 처리, 되돌리기, 히스토리 |
| `0005_feedback.sql` | 역할 선택, 메모, 폐기, 소셜 가입 대응 |
| `0006_notices.sql` | 공지, 확인 기록 |

### 5. 실행

```bash
npm run dev
```

http://localhost:5173 에서 열려요.

### 소셜 로그인 (선택)
1. Supabase **Authentication → URL Configuration**에서 Site URL과 Redirect URLs에 앱 주소를 등록해요.
2. **Sign In / Providers**에서 Google과 Kakao를 켜요.
3. 구글·카카오 개발자 콘솔의 리다이렉트 URI에는 `https://<프로젝트>.supabase.co/auth/v1/callback`을 등록해요.
4. **카카오 주의:** Supabase가 이메일(`account_email`)을 항상 요청해서, 카카오 앱에 이메일 동의항목이 없으면 KOE205 오류가 나요. 개인 개발자는 본인인증으로 비즈 앱 전환을 한 뒤 이메일을 선택 동의로 켜면 돼요.
